# Segmentation-assisted continuous localization

English | [中文](README.zh.md)

## Scope

This experimental CPU implementation predicts planar pose from odometry and corrects it against measured depth surfaces selected by synchronized semantic masks. Diagnostic mode uses labels from perception. Feedback mode can request SAM for a current frame.

## Run

From the inner `steward` directory, install the optional dependency with `python -m pip install -e ".[localization]"`. SciPy supplies the distance transform and robust least-squares solver; no ROS, RTAB-Map or native build is needed. The optional dependency is recorded in `uv.lock` too.

From the inner `steward` directory, run `python -m steward.cli build-kitchen` if the puzzle scenarios have not been generated. Then run `python -m steward.cli up --scenario puzzle-dog --phase phase1-sam --localization-experiment --no-dispatch-task` and open `http://127.0.0.1:7400`. This uses the configured SAM service and the shared Ego Runtime. Select **定位建图** to compare the estimated and simulator trajectories, walls and zero-distance map cells.

Ordinary runs retain instantaneous odometry noise with cumulative drift and localization off. The experiment switch combines `--odom-drift` (1% translation scale bias and 0.005 rad/m heading drift) with `--apply-localization` (fused pose drives Ego-State and shared-runtime control). Use either option independently on `up`. For separate processes, pass `--odom-drift` to `world` and `--apply-localization` to `ego`. Apply mode uses the default TOML when omitted. Pass `--localization-config config/localization.toml` alone to collect diagnostic output, or combine it with apply mode to use a custom TOML.

For a compatible in-process motion test, append `--localization-experiment` to its normal pytest command. Pytest also accepts either `--odom-drift` or `--apply-localization` alone and an optional `--localization-config` for feedback. Feedback tests use simulation semantic labels on world instance masks by default. For scenarios without world masks, use `--localization-mask-source=sam` and provide the configured segmenter. Use the experiment runner or motion matrix below for the room loop, large-angle turns, stationary runs and dog puzzle.

Read `GET /ego/localization` from that instance's Ego API. Disabled localization returns `enabled: false`. Enabled output contains `rawPose`, corrected/predicted `pose`, `mapFromOdometry`, timestamp, episode, state, rejection reason, map version, correction age and metrics. The runtime also appends `localization.jsonl` to its observations directory. The console and Observer score Ego-State. With feedback enabled, its body and newly fused observations use the corrected map frame; diagnostic mode leaves them unchanged.

## Selection and matching

The shipped configuration uses `wide_camera`. It selects walls, cabinets, counters, sideboards and tables using synchronized semantic labels. The winning label must pass the score threshold. Missing or anonymous masks contribute no points.

Mask erosion excludes boundary mixing. Calibrated backprojection and body kinematics remove the robot and select approximately vertical surfaces. Spatial sampling and per-region limits prevent large regions from dominating the shared point budget.

The first sufficient observation seeds a local surface map. Subsequent observations match against the historical map before insertion. Each of the three height bands has a two-dimensional unsigned distance field with 5 cm spacing. Bilinear lookup scores the transformed points. Optimization adjusts planar translation and heading. The EKF owns the odometry prior. The set of matching points stays fixed during fitting.

Acceptance checks overlap, inlier fraction, RMS surface distance, optimization status, correction limits and geometric information without the odometry prior. The angular information column is scaled by the point lever arm for the degeneracy ratio; the unscaled Jacobian determines visual covariance in metres/radians. A weak information eigenvalue ratio rejects the entire correction; partial correction along observable directions is not implemented. EKF gating then accepts or rejects the visual candidate. Rejected frames cannot update the map or correction transform. Accepted frames insert points using the fused pose only, after sufficient translation or rotation.

Between observations, raw odometry is composed with the last map-from-odometry correction. `initializing` denotes the first map observation, `corrected` an accepted match and `predicted` an odometry-only update or rejected match. `accepted` marks only the current successful match. `stale` means there has never been a successful correction or its age exceeds `stale_after_s`; it is not a calibrated covariance or a navigation safety decision. Duplicate/non-increasing timestamps fail in the tracker and are skipped by the runtime when a frame was already processed; episode changes reset map and correction.

## EKF fusion

The `[ekf]` table enables a three-state `(x, y, yaw)` filter by default inside this opt-in experiment. Body-relative odometry increments propagate pose with the SE(2) Jacobian. Process variance grows with elapsed time and measured motion; motion is measured over configured coarse intervals with deadbands, so frequent absolute sensor jitter is not counted as metres of independent travel. The covariance retains an odometry sampling-noise floor. These are configurable approximate noise models, not calibrated confidence guarantees.

Visual covariance uses the inlier geometry Jacobian and residual scale, with a rasterization floor, separate position/yaw and map-error floors, capped effective point count and covariance inflation. The filter wraps heading innovation, rejects excessive visual uncertainty and normalized innovation squared (NIS), and spaces accepted observations by at least `min_visual_interval_s`. The default NIS limit is 11.345. Accepted observations use a Kalman gain and Joseph-form posterior covariance; invalid covariance fails explicitly, and rejected observations do not change the predicted pose/covariance or the map.

Output includes `filterCovariance`; candidate metrics include `candidatePose`, `visualCovariance`, `innovation`, `innovationNis`, `predictedCovariance` and, after fusion, `kalmanGain` and `fusedDelta`. `delta` remains the optimizer's proposed change, while `fusedDelta` is the applied filter change. A successful update reports `ekf_fused`; filter rejections include `innovation_outlier`, `visual_uncertainty` and `correlated_observation`. Prediction and covariance continue after rejected visual observations; the correction age is reset only by an accepted update.

Set `[ekf].enabled = false` to reproduce the earlier direct-visual-correction mode and its weak optimizer priors (`prior_position_sigma_m`, `prior_yaw_sigma_rad`). Enabled mode removes those priors from the visual objective to avoid applying the same motion prior twice. A self-built map, repeated views and odometry-based initialization still correlate observations; covariance floors and spacing are conservative approximations, not an exact joint map/trajectory filter. The implementation does not estimate velocity or calibration biases, undo historical map errors or guarantee globally consistent mapping. Applying output to Ego-State requires the separate feedback flag.

## Configuration and limits

The localization TOML configures camera selection, sampling, map resolution and acceptance thresholds. Feedback mode samples `wide_camera` once per simulated second and uses labels from that capture timestamp. It requests SAM if the frame lacks labels, and continues odometry prediction between observations. SAM failures appear in localization status and operator alerts. [Configuration](../../config/localization.toml)

The layered map starts at 5 m × 5 m in the plane. Accepted insertions expand all layers together to include observed hits and the distance-query margin. Existing grid points retain their map coordinates. The map clears a historical hit after three eligible insertions observe free space near it. A ray must pass the cell near its recorded height and reach a deeper surface. Hits in the same cell reset its free-space count. The count of removed cells appears as `mapClearedCells`. If either dimension would exceed 1,025 grid points, localization reports `map_grid_limit` and preserves the previous grid.

Set `dynamic_map = false` and `map_size_m = 20.0` in a configuration copy to run the layered map with fixed bounds. The localizer continues odometry prediction when observations have insufficient overlap with the historical surface.

## Feedback coordinates

In the console, open **定位建图** to compare the simulator wall outlines with zero-distance grid cells and both trajectories. The height selector shows one layer or overlays the translucent colors for all layers. The displayed clearing count resets when the episode changes.

Feedback publishes an immutable map-from-odometry snapshot. Perception headers and live body reads are copied into that frame before Ego-State updates or skill planning; raw localization input is preserved. Already projected headers are not corrected twice, episodes reset the snapshot, and yaw retains its unwrapped turn count. The map remains anchored at initialization: existing stationary tracks stay fixed and new observations enter the same frame. Historical map distortion is not retrospectively optimized.

The simulator accepts base position-servo targets in its startup-calibrated actuator reference. Commands retain that convention; this adapter does not reinterpret targets as drifting sensor coordinates. A different physical robot needs an adapter matching its own actuator reference. SAM runs outside the Ego-State lock, but its latency still delays perception; prediction-only intervals and original task deadlines remain relevant.

The experiment runner `scripts/localization_experiment.py` takes a new output directory and runs the room loop and long yaw sweeps with simulated semantic masks at 1 Hz. Pass `--cases stationary` for five simulated minutes without movement commands. The test shares the same simulated RGB-D frames between the native-noise case and a case with a linear bias added to measured x and yaw. It samples odometry at 10 Hz, processes vision at 1 Hz, checks physical motion against simulator truth and records both trajectories. The first and last 30-second mean pose errors show long-term offset separately from per-sample jitter.

The simulation adapter exists only in the pytest experiment process. It associates the existing shuffled instance masks with simulated category labels (score 1.0), retaining mask degradation and depth/odometry noise. Only localization receives those labels; primary object perception is unchanged. The adapter supplies no GT robot poses, entity identifiers or GT map, and an assertion forbids SAM calls. This measures an ideal-semantics iteration rather than SAM accuracy. The no-drift feedback dog-puzzle case saves its actual terminal MuJoCo scene before shutdown as `final-world.png`, with camera/time metadata; a failed test saves its failure scene too. ## Validation and first measurement

Run `python -m pytest tests/test_pose_ekf.py tests/test_distance_localization.py tests/test_segmenter.py -q` for weighted fusion, wrapped innovations, large-jump rejection, covariance stability, fused-only map insertion, deterministic pose correction, prediction continuity, degeneracy rejection, timestamp/episode isolation, semantic selection, same-frame reuse without additional model calls, HTTP output and existing segmentation regressions. Tests use private temporary directories and dynamically allocated HTTP ports. They contain no machine-dependent speed assertions.

For a real SAM smoke, run `python scripts/diagnose_segmented_localization.py --output var/localization/my-smoke --frames 8` with a fresh output directory. It builds a private kitchen, physically turns the robot, gets mask-free RGB-D, asks the configured SAM service, and saves labelled RGB-D inputs and per-frame outputs. GT is recorded only after localization for scoring. This standalone diagnostic requests SAM itself. Errors propagate and the private simulation is closed.

The first pre-EKF seed-0 smoke used eight frames: one seeded the map and seven accepted a correction. Selection plus localization averaged 85.94 ms with P95 103.74 ms; total capture was 0.284 s and SAM was 37.752 s. Raw position RMSE was 0.481 cm and continuous output RMSE 1.874 cm. This short mostly rotational run worsened position accuracy; it establishes execution of the real-mask pipeline, not an improvement in drift, full-loop coverage or real-time end-to-end operation. It is not directly comparable to the earlier head-camera RTAB-Map benchmark. Generate replay input with the smoke command above.

Replay those fixed predictions without rendering or SAM using `python scripts/diagnose_segmented_localization.py --replay var/localization/my-smoke --output var/localization/my-replay --frames 8`. The saved masks and labels belong to each frame's sensor timestamp. Replay outputs report selection and localization timing only; they contain no GT-derived input or fresh segmentation inference.

The existing room-loop test also has a `segmented` group, sampling real SAM once per simulated second while propagating pose at every body sample. It is skipped unless `STEWARD_SAM_LOCALIZATION_E2E=1`; then `python -m pytest tests/test_localization_loop.py -k segmented -q -s` runs its three seeds. It saves raw and continuously predicted/corrected errors, accepted-observation share, longest interval without accepted correction, raw trajectory hash and capture/SAM/selection/localization times. Its case time excludes simulation closure. The [full serial experiment](results/segmented-room-loop-20261117/summary.json) completed all nine cases: position RMSE decreased for all three seeds, while correction gaps and SAM latency remain significant. The ordinary integration test separately verifies a complete physical loop with empty semantic results using a stand-in, not SAM accuracy.

The large-angle reversal case is `python -m pytest tests/test_localization_rotation.py -q -s`. It commands 0° → +200° → −200° → +200° → −200° → 0° at 0.6 rad/s, with one second settling at each target and one semantic observation per simulated second. Intermediate commands preserve the long 400° reversals rather than choosing the shortest wrapped turn. GT checks each signed sweep, approximately 1600° total travel, repeated ±π crossings and less than 3 cm actual base displacement. Localization still receives no GT.

Without the opt-in environment variable, this case verifies prediction with empty semantic results; `STEWARD_SAM_LOCALIZATION_E2E=1` also runs real SAM for seeds 0, 1 and 2. It reports full-trajectory position and wrapped heading errors, accepted-observation share, longest correction gap and capture/SAM/selection/localization timing. Real-SAM cases save synchronized labelled RGB-D under each test directory's `inputs`, compatible with the diagnostic script's `--replay`. Case time starts after simulation construction and ends after simulation closure; it includes observation logs and input snapshots but excludes final report and trajectory CSV writes. Noise is unchanged, and the existing cumulative heading bias depends on translation distance, so this primarily tests view changes, angle wrapping and registration stability rather than injected rotation-dependent drift. Accuracy improvement is not asserted.

The [pre-EKF reversal experiment](results/segmented-rotation-20261117/summary.json) completed all four cases. Both position and heading RMSE increased for all three real-SAM seeds, and two runs accepted large false translation corrections despite millimetre-scale true displacement. Small endpoint error concealed substantial intermediate error. These results expose a limit of direct visual correction; the room-loop benefit does not establish rotational stability. No localization parameters were changed for that experiment.

`scripts/replay_localization_case.py` replays a rotation recording at its original body cadence, including prediction between semantic frames. Supply `--source` with a directory containing `trajectory.csv` and `inputs/frame-*.npz`, and `--output` with a fresh directory. The default configuration evaluates EKF; `--legacy` disables it and checks every replayed pose against the earlier recording. Ground truth is read for scoring only after each estimator output. This differs from the short diagnostic's observation-only replay and makes no fresh SAM requests.

The [fixed-input EKF rotation comparison](results/segmented-ekf-20261117/rotation-comparison.csv) preserves the original body cadence and verifies legacy reproduction for all three seeds. EKF keeps position errors close to raw odometry instead of introducing the earlier large shifts. The [fresh-SAM EKF room-loop comparison](results/segmented-ekf-20261117/room-loop-comparison.csv) has identical raw trajectories to the earlier runs but new segmentation inference; two seeds improve and one remains approximately equal. Covariance is approximate, correction gaps remain, and neither result establishes global or real-time reliability.
